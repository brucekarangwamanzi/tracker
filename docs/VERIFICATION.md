# Verification record

Verified on 19 October 2026 using Node **22.23.3** and an isolated PostgreSQL **16.15** instance. The application connection used a restricted role without SUPERUSER, BYPASSRLS, DELETE or DDL rights.

- After the offline/online update, strict backend TypeScript checking and `npm test` with `TEST_DATABASE_URL` set pass: **68 tests across 7 files; none skipped**. Earlier full `npm run check` also verified schema generation and Prisma client generation. API coverage includes browser preflight, allowed origins, and continued token enforcement.
- `npm run mobile:test`: **12 tests passed**, including real SQLite through `sql.js` and five connection/sync-status tests. Covers sample balance reconciliation, soft-delete undo and remembered wallet, dependency-ordered private defaults, linked loan payments, queued version ordering, decimal/overpayment rejection, rapid concurrent local payments, and extra-payment simulation. Only native bridge modules are mocked.
- `npm run mobile:check`: Expo strict TypeScript and lint pass. Backend and Expo tests have separate runner configurations; React Native Flow sources are not parsed by the backend runner.
- Expo exports succeed for **web, Android, and iOS**. These are JavaScript/Hermes bundles, not signed native binaries or device tests.
- The app is served at `http://localhost:8080`. HTTP checks return 200 for the app shell and nested routes; three initial scripts and both SQLite worker/WASM assets return successful responses. HTML and assets carry `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`; WASM has `application/wasm`. Missing assets return 404 and unsupported methods 405.
- Four service-worker tests use a Node VM harness, covering revision changes, offline routes and SQLite assets, retained isolation headers, excluded financial/auth requests, failed installation, and cache cleanup. An additional real SQLite test reopens an offline database after a failed push, accepts the original queued operation on reconnect, and verifies replay creates no duplicate. These are not browser tests.
- The exported web app now includes 59 precached static files plus a root-scoped service worker and web manifest. The running server serves these with isolation headers and the correct JavaScript/manifest/WASM MIME types. See [offline and online behavior](OFFLINE.md).
- The refreshed API returns 200 for `/health` and 401 for an unauthenticated `/dashboard`. Authentication was not bypassed for the local demo.
- Five real PostgreSQL tests: RLS/ownership and denied hard deletion, BIGINT preservation and replay, rollback after a later constraint failure, concurrent loan-payment conflict handling, commit-ordered paginated pull.
- Five real SQLite tests using `sql.js`: values above JavaScript’s safe-integer boundary remain SQLite integers; atomic local transfer; queued revision acknowledgments; preservation of dirty drafts and server shadows; invalid pull rollback and cursor integrity.
- Unit/API/job tests cover the remaining algorithm cases, asymmetric JWT verification, HTTPS enforcement, reminder deduplication and transient/permanent push failures.
- Initial PostgreSQL migration applied successfully to a fresh disposable database.
- After freezing the bootstrap migration generator and improving the development command, schema generation and TypeScript checking were rerun.
- The backend audit reported **0 known vulnerabilities** after compatible updates. The separate Expo app audit currently reports **27 affected dependencies** (19 high, 8 moderate), cascading from advisories in [braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), [node-forge](https://github.com/advisories/GHSA-86w9-cpqp-85rv), and [uuid](https://github.com/advisories/GHSA-w5hq-g745-h8pq). Compatible fixes were applied. npm proposes an incompatible Expo 44 downgrade for remaining fixes; that was not applied. See [mobile limitations](MOBILE.md). Both dependency trees have lockfiles.
- Local handoff/documentation links were checked.

Browser testing was explicitly declined by the user. No browser rendering, screenshot, responsive-layout, accessibility traversal, or click-through verification is claimed. HTTP and repository tests confirm their respective layers, not a browser end-to-end pass.

Not verified against live services: a real Supabase account or key rotation, physical Expo iOS/Android devices, biometric prompts, SecureStore/SQLCipher, actual Expo push delivery, TLS proxy deployment or backup restoration. Push providers were mocked; no real notifications were sent. Native source and configuration are implemented; native signing, cloud setup, and device integration instructions describe remaining setup, not completed live infrastructure.
